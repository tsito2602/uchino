# uchino

レシピを保存し、人数に合わせて分量を変更できるReact / HonoのPWA。Cloudflare Workersのstaging向け初期実装です。

## できること

- 手入力でのレシピ保存・編集・削除、カテゴリ・材料検索、お気に入り
- 料理写真の登録・変更・削除、写真全面の2カラム一覧と詳細表示
- 人数に合わせた分量変更（分数対応、少々・適量は維持）
- レシピと独立した買い物メモ、材料を選んで買い物へ追加
- IndexedDBへの端末内保存、PWAのオフライン表示と手動更新
- 設定から実データ／デモデータを切り替え（レシピ・買い物メモを分離）
- ライト・ダーク・端末設定に合わせた外観
- GoogleログインとD1を設定した場合のアカウント別保存・同期
- 対応サイトのJSON-LDレシピ取り込み、AI設定後の画像・本文取り込み

初期デプロイ直後は「この端末で使う」から利用できます。Google認証・D1・AIの実設定がない機能を動作済みとして扱いません。端末モードのデータとGoogleアカウントのデータは分離しています。Googleログイン時の自動移行は行いません。

## 開発

Node.js 24を利用します。

```sh
npm ci
npm run check
npm run dev:worker
```

フロントをホットリロードする場合、別ターミナルで `npm run dev` を実行します。APIは `127.0.0.1:8787` にプロキシされます。単体プレビューはビルド後に `node scripts/preview.mjs` でも起動できます（認証・D1・AIなし）。

## stagingを初期作成

```sh
npx wrangler login
npm run deploy:staging:initial
```

このコマンドは検証後、Cloudflareアカウント内の `uchino-staging` D1を作成または再利用し、`wrangler.staging.jsonc` にそのIDを記入、マイグレーションを適用して `uchino-staging` Workerへ公開します。既存のuchiwakeや旧uchinoのDBには接続しません。初期作成後、更新された設定ファイルをstagingブランチへコミットしてください。

以後の更新:

```sh
npm run db:staging
npm run deploy:staging
```

詳細は [stagingの設定](docs/STAGING.md) を参照してください。

## 保存と同期

料理写真はレシピごとに1枚登録できます。20MB以内のJPEG・PNG・WebP、または端末で読み込めるHEIC/HEIFに対応し、端末上で長辺1280px以下・256KB以下のJPEGに変換します。写真はレシピと一緒にIndexedDBへ保存し、Googleログイン時は既存のD1同期とJSON書き出しにも含まれます。写真の変換中は保存を止め、読み込みに失敗しても元の写真は残します。HEICに対応しないブラウザではJPEGへの変換を案内します。

サンプル3品と取り込みデモには生成した料理写真を同梱しています。設定の「表示するデータ」から実データ／デモデータを切り替えられます。選択は端末・Googleアカウントごとに記憶し、デモのレシピと買い物メモは専用の端末内領域へ保存します。デモでの編集・削除は実データやD1へ同期しません。空画面の「サンプルを見てみる」もデモ側へ切り替えます。

旧サンプルボタンで保存した3品と旧取り込みデモは、編集内容を保持してデモ領域へ移します。元のサンプルとデモ側に異なる編集があれば両方を残します。コピーと移動は同一のIndexedDBトランザクションで行い、Google同期済みの旧サンプルには移動元の削除を同期します。自分で作成した通常のレシピや既存の買い物メモは移動しません。既存サンプルにも写真を表示し、明示的に削除した写真やレシピは復活させません。デモ写真はService Workerでキャッシュします。書き出しは表示中の領域だけを対象にし、ファイル名とJSONにデータ種別を含めます。

端末モードではデータはそのブラウザのIndexedDBにのみ保存されます。Googleログイン後の変更も先に端末に保存し、オンライン時にD1へ同期します。未同期件数は設定に表示します。通信失敗では変更を保持します。同時編集の競合時は上書きせず通知し、未同期内容をJSONに書き出して保管できます。初期版では競合の自動統合・他ユーザーとの共有・JSONの復元取り込みは未実装です。

API・認証応答はService Workerにキャッシュしません。Service Workerの更新は設定から実行し、未同期中は更新を止めます。ローカル保存はバックアップではないため、ブラウザのデータ消去や端末変更の前に設定から書き出してください。

## 流用元

`tsito2602/uchiwake` main `3f93e552ba743055972b6051a52c492c721729a3` の共通UI、外観設定、Google認証実装を流用しました。取得時点でuchiwakeのmainにAGENTS.mdはありません。uchinoは空リポジトリから初期化しています。

### レシピ取り込みの確認とstagingデモ

URL・画像・本文の取り込み後は、元資料と読み取り結果を確認し、人数・材料・手順を編集してから保存します。「要確認」には仮設定や曖昧な箇所の理由を表示します。取り込み中は左の戻る操作で中止して再試行できます。

`APP_ENV=staging` のときだけ、デモデータ表示中の取り込み画面の「デモで試す」が使えます。GoogleログインやAI設定なしでも演出・確認・編集を試せます。「サンプルとして保存」を押すとデモ領域にだけ保存し、D1への同期は行いません。`/api/import/demo` はstaging以外で404を返します。本番でデモを有効にするクライアントフラグはありません。

取り込み演出の参照元とバージョンは `IMPORT_UI_SOURCES.md` に記録しています。
